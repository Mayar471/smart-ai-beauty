# خيارات محرك الصور — قرار قبل التنفيذ

تاريخ المراجعة: 17 أكتوبر 2026. هذه مقارنة وترشيح للاختبار، وليست إعلان اتصال أو نجاح أي محرك جديد.

**تحديث بعد البحث الموسع:** وُجدت خيارات API مجانية تستحق الاختبار، أهمها Qwen-Image-Edit-2511 عبر ModelScope بالنقاط، وKolors عبر SiliconFlow، إضافة إلى بديل Cloudflare. تفاصيل الحصص وشروط الحساب والقدرات في [البحث الموسع](CHINESE_IMAGE_MODELS_RESEARCH.md)، وهو المرجع الأحدث لاختيار الخدمة المجانية.

مصادر القراءات: Node os، وnvidia-smi، ومعلومات BIOS من سجل Windows، وstatfs. مُنع الوصول إلى WMI/CIM حتى بعد إعادة المحاولة؛ لم تُجمع أرقام تسلسلية أو معلومات شبكات. السعة المقروءة تخص وحدة C: وليست إثباتاً لنوع القرص أو كل الأقراص.

**الاستنتاج الهندسي:** لا أوصي باعتماد هذا الجهاز كخادم لتوليد الصور المطلوبة. المشكلة الأساسية VRAM البالغة 2GB. نقل أجزاء النموذج إلى RAM/CPU قد يتيح تجارب في بعض الإعدادات، لكنه ليس دليلاً على سرعة أو استقرار مناسبين للموقع. المساحة الحرة وحدها لا تعوّض ذاكرة GPU. يبقى الجهاز مناسباً لتطوير وتشغيل واجهة الموقع وخادم Node والمعاينات المحلية الحالية.

| --- | --- | --- | --- |
| CatVTON | تلبيس قطعة مرجعية على صورة شخص | [المستودع الرسمي](https://github.com/Zheng-Chong/CatVTON) | كود وأوزان للاستخدام غير التجاري بشروط CC BY-NC-SA 4.0؛ يذكر نحو 8GB VRAM عند bf16 ودقة 1024×768. لا يغيّر التسريحة ولا يضمن إطلالة متعددة القطع كاملة. |
| Qwen-Image-Edit-2511 | تحرير صورة الشخص بتعليمات وصور مرجعية، مرشح للشعر وتركيب الإطلالة | [المستودع الرسمي](https://github.com/QwenLM/Qwen-Image)، [بطاقة النموذج](https://huggingface.co/Qwen/Qwen-Image-Edit-2511) | نموذج مفتوح؛ يحتاج تنزيلات وتشغيلاً على موارد مناسبة. لا نفترض أن متطلبات CatVTON تكفي له. دعم تعدد الصور وتحسين ثبات الشخصية لا يضمن جودة صور المشروع. |
| FLUX.2 klein 4B | محرك موحد لتوليد وتحرير الصور بعدة مراجع | [بطاقة النموذج الرسمية](https://huggingface.co/black-forest-labs/FLUX.2-klein-4B)، [API المزود](https://bfl.ai/) | نسخة الأوزان 4B بترخيص Apache 2.0، وبطاقتها تذكر نحو 13GB VRAM. API مستضاف مدفوع؛ نراجع السعر عند اختيار النموذج، ولا نفترض أن كل إصدارات FLUX لها الترخيص نفسه. |
| Gemini 3.1 Flash Lite Image | API لتحرير الصور، مرشح لاختبار ملابس وشعر بمراجع | [التسعير والتوفر الرسمي](https://ai.google.dev/gemini-api/docs/pricing#gemini-3.1-flash-lite-image) | لا حصة مجانية معلنة لهذا النموذج في جدول API الحالي. خرج صورة 1K نحو 0.0336 دولار، إضافة إلى المدخلات والنص والمحاولات. نحو 3.36 دولار لخرج 100 صورة فقط؛ ليس سعراً نهائياً شاملاً. |

أسماء المحركات ليست بديلاً عن الاختبار. لا نعد بتطابق الوجه أو تطريز القطعة أو طولها أو ملاءمة مقاسها قبل تجربة الصور الحقيقية ومراجعتها.

## الاختيار المقترح مع شرط المجانية

1. إن أمكن توفير GPU من الجامعة أو جهاز آخر تحت سيطرتنا، نبدأ باختبار CatVTON للملابس. نحو 8GB حد مذكور لتشغيله، وليس ضماناً لكل خط المعالجة. ثم نقيم محرر الصور للشعر بحسب ذاكرة الجهاز الآخر؛ لا نَعِد بتشغيل Qwen أو FLUX على الجهاز نفسه قبل الفحص.
2. إن توفر GPU بذاكرة تلائم FLUX.2 klein 4B، فهو مرشح لاختبار محرك واحد للملابس والشعر أولاً. هذا يقلل تعقيد الدمج إن نجحت الجودة؛ الترشيح هندسي وليس نتيجة اختبار لهذا المشروع.
3. قبل طلب GPU خارجي نقيّم الآن Qwen-Image-Edit-2511 عبر حصة ModelScope المجانية، أو بديل Cloudflare المجاني. أهلية الحساب والجودة بحاجة لاختبار فعلي؛ لا نفعّل فوترة عند نفاد الحصص. مفتاح Gemini النصي لا يفعّل خدمات الصور الأخرى.
4. حصص GPU أو الديمو المجانية قد تصلح لتجربة محدودة عند توفرها؛ لا نعتمدها كخادم دائم أو نعد بتوفرها أثناء المناقشة.

وجود الأوزان على Hugging Face يعني مكاناً لتنزيل النموذج، وهو مختلف عن تشغيله عبر Space عام. تعطل الديمو السابق لا يثبت فشل النموذج على كل استضافة، لكنه أيضاً لا يثبت أن إعادة استضافته ستحسن الجودة؛ نختبر التوفر والجودة كلّاً على حدة.

## كيف يرتبط المحرك بالموقع

الموقع → خادم Node الحالي → مهمة على خادم GPU خاص بنا أو API الصور المتفق عليه → صورة فعلية ونتيجة/خطأ → حفظ النتيجة لحساب صاحبتها وتنزيلها.

عند استخدام ComfyUI على GPU مناسب يمكن إرسال workflow عبر [واجهات الخادم الرسمية](https://docs.comfy.org/development/comfyui-server/comms_routes). ComfyUI يدير تنفيذ النموذج وليس بديلاً عن النموذج أو GPU. يُحصر الوصول في الخادم المصرح، ولا نفتح واجهة GPU للعامة.

Gemini النصي يبقى للمناسبة والطقس واقتراح القطع. محرك الصور يستقبل الصورة والمراجع والتعليمات عند طلب المستخدمة، بعد توضيح الوجهة إن كانت خارج الجهاز. لا يُرسل مفتاح Gemini إلى مزود آخر.

## تجربة إثبات قبل تطوير الواجهة مجدداً

- نبدأ بصورة جسم أمامية واضحة وصورة وجه وصور قطع واضحة؛ الصورة المقتطعة أو الصغيرة لا تعطي تفاصيل مفقودة مؤكدة.
- تجربة أولى: تطبيق قميص واحد مع إبقاء الوجه والوضعية والخلفية قدر الإمكان.
- تجربة ثانية: تغيير التسريحة فعلياً، مع إبقاء ملامح الشخص.
- تجربة ثالثة: علوية وسفلية مع التسريحة المختارة، ثم الألوان المحلية للمكياج عند الحاجة.
- نراجع اختلاف الوجه، شكل الجسم والوضعية، حدود الشعر، مطابقة تفاصيل القطعة، الأبعاد، الزمن والكلفة. لا نضع زر «توليد» بوصفه عاملاً إلا بعد نجاح مسار فعلي من الموقع إلى الصورة.

لم يُنزّل نموذج أو يُفعّل API مدفوع أو تُرسل صور شخصية خلال هذه المقارنة. الخطوة التالية هي اختبار أهلية حساب مزود مجاني ثم استدلال فعلي ومراجعة الجودة، أو توفر GPU مناسب خارج MX450. يبقى شرط الميزانية صفر معتمداً.
