# بحث نماذج الصور الصينية والخدمات المجانية للمشروع

تاريخ التحقق: **17 أكتوبر 2026**. هذا تقرير بحث واختيار تقني؛ لا يعلن نجاح ربط مزود جديد أو توليد صورة فعلية. المرجع بصيغة Markdown حسب طلب صاحب المشروع.

## القرار المقترح

**المرشح الأول للاختبار هو Qwen-Image-Edit-2511 عبر ModelScope API Inference.** يدعم تحرير الصور بمراجع متعددة، وتوجد له واجهة API رسمية بحصة تُكتسب مجاناً بالنقاط. ملاءمته للشعر والملابس أعلى من نموذج يولد شخصاً جديداً من وصف نصي فقط. يبقى نجاحه على صور مشروعنا غير مقاس حتى الآن.

وجد البحث أيضاً **Kolors عبر SiliconFlow** بسعر صفر معلن، و**CogView-3-Flash عبر BigModel** المعلن مجاناً. الأول لديه مثال إدخال صورة؛ الثاني يولد من النص. لا توجد نتيجة بحث تثبت أن أيّاً منهما يضمن الحفاظ على نفس الوجه وتطبيق عدة قطع ملابس وتسريحة محددة معاً.

شرط «لا ندفع أي مبلغ» قابل للتحقيق ضمن حصص خدمات مجانية أو موارد جامعة متاحة. أما استضافة مجانية غير محدودة، مع توافر دائم وجودة ثابتة، فلم يثبتها البحث. لا نفعّل انتقالاً إلى خدمة مدفوعة عند نفاد الحصة.

## كيف جرى الفحص وما حدوده؟

- بحث بالعربية والإنجليزية والصينية، مع الرجوع إلى وثائق المزودين ومستودعات الفرق وبطاقات الأوزان.
- مراجعة 18 مستودعاً رسمياً: 15 README محفوظة كأدلة عمل، إضافة إلى LongCat-Image وCogView4 وERNIE-Image عبر الويب. فُحصت الوظائف، إتاحة الأوزان، شروط الترخيص، ومتطلبات الذاكرة المعلنة.
- فتح وثائق ModelScope الديناميكية في المتصفح، وقراءة شروط الحساب وحدود API ونظام النقاط وصفحة النموذج؛ لم نكتفِ بمقتطف بحث قديم.
- فحص تسعير SiliconFlow ومخطط طلب الصور، ووثائق BigModel، وتجارب Alibaba/Tencent، وبديل Cloudflare، وحدود Colab.
- **لم يُجرَ استدلال مصادق عليه** لدى المزودين الجدد؛ لا تتوفر مفاتيحهم في هذا الفحص. فتح الوثائق يثبت ما تعلنه الخدمة، ولا يثبت نجاح حسابنا أو زمن التنفيذ أو جودة صورنا.
- لم نرفع صور المستخدمين، ولم ننشئ حسابات أو نفعّل فوترة أو ننزّل أوزاناً ضخمة. ما بقي من أهلية الحساب والمنطقة يُختبر لاحقاً دون افتراض أنه مضمون.

## ما نوع المحرك الذي نحتاجه؟

| المهمة | المطلوب تقنياً | هل يكفي التوليد من النص؟ |
| --- | --- | --- |
| صورة إلهام لأوتفيت | Text-to-Image | نعم، إذا كان مسموحاً ظهور شخص افتراضي |
| تغيير تسريحة المستخدمة | تحرير صورة مع المحافظة على الهوية، ويفضل قناع لمنطقة الشعر | لا |
| تلبيس قميصها الحقيقي | صورة الشخص + صورة القطعة؛ محرر متعدد المراجع أو Virtual Try-On | لا |

هذه متطلبات هندسية للمشروع، وليست ادعاءً بأن نموذجاً بعينه يحققها دون اختبار. النموذج الذي يقبل صورة واحدة لا يصبح تلقائياً محرك تلبيس دقيقاً. وتركيب صور في لوحة مرجعية لا يُعد توليداً لصورة ترتدي فيها المستخدمة القطع.

## 1. ModelScope + Qwen-Image-Edit-2511

### ما تأكد من النموذج؟

فريق Qwen يتيح الأوزان، ويشرح تحسين ثبات الشخصية وتحرير الصور ودمج المراجع. نسخة 2511 مرشح محدد قابل للفحص، بخلاف الاكتفاء باسم Qwen العام. ترخيص هذه النسخة Apache 2.0 وفق بطاقة الأوزان. هذا يجعلها خياراً مناسباً للتجربة؛ التقييم المعلن من الفريق لا يغني عن تقييم ملابسنا وشعرنا. [المستودع](https://github.com/QwenLM/Qwen-Image)، [بطاقة الأوزان](https://huggingface.co/Qwen/Qwen-Image-Edit-2511).

### ما تأكد من الاستضافة المجانية؟

وثيقة ModelScope تعلن API Inference مجانياً للمسجلين، وتشترط ربط حساب Alibaba Cloud وإكمال توثيق الهوية. وتوثق إدخال الصور المحلية بصيغة Base64. هذا يحل مشكلة تمرير صور مخزنة محلياً دون نشرها على رابط عام، لكنه يظل إرسالاً للصور إلى المزود الخارجي. [طريقة الاستخدام](https://modelscope.cn/docs/model-service/API-Inference/intro).

الحدود الحالية تعتمد Magicubes، مع تقييد ديناميكي للتزامن، والخدمة مخصصة للتجربة وليست ضمان SLA أو تشغيل تجاري كثيف. صفحة Qwen 2511 تعرض تقديراً **2 نقطة للطلب** ومثال API. لذلك لا نعتمد ادعاء «2000 صورة يومياً» المتداول في شروحات قديمة. [حدود الخدمة](https://modelscope.cn/docs/model-service/API-Inference/limits)، [صفحة النموذج ومثال API](https://modelscope.cn/models/qwen/Qwen-Image-Edit-2511).

### الحصة بالأرقام الحالية

برنامج المكافآت يذكر 200 نقطة عند تسجيل الدخول يومياً، و50 نقطة يومية إضافية عند الدخول بعد ربط Alibaba Cloud. النقاط قصيرة الأجل تنتهي، ولا تتراكم كرَصيد دائم؛ توجد مكافآت أخرى لا نعتمد عليها في تقديرنا الأساسي. [قواعد Magicube](https://modelscope.cn/docs/magicube/intro).

**حساب تقديري، وليس حصة صور مضمونة:** إذا حصل الحساب فعلاً على 250 نقطة، وظل الطلب بنقطتين، وكانت النقاط كلها لهذه المهمة، فهذا يعادل نحو **125 طلباً**. الإطلالة التي تحتاج طلبين تستهلك ضعف ذلك، والمحاولات الإضافية تخفض عدد الإطلالات المقبولة. نتأكد من رصيد الحساب والتكلفة الظاهرة قبل الاستخدام.

وجود مكافأة دخول يعني أن هناك إدارة دورية لحساب المطور. أما عملية المستخدمة داخل الموقع فتبقى تلقائية عبر API؛ لا حاجة لنسخ صورها يدوياً بين التطبيقات.

### شكل الربط الذي تسمح به الوثائق

```http
POST https://api-inference.modelscope.cn/v1/images/generations
Authorization: Bearer <MODELSCOPE_TOKEN>
Content-Type: application/json
X-ModelScope-Async-Mode: true
```

```json
{
  "model": "Qwen/Qwen-Image-Edit-2511",
  "prompt": "Preserve the person's identity. Apply the selected hairstyle and the referenced clothing. Produce one coherent full-body photograph.",
  "image_url": [
    "data:image/jpeg;base64,<PERSON_IMAGE>",
    "data:image/jpeg;base64,<GARMENT_IMAGE>"
  ]
}
```

هذا مخطط طلب مرجعي مأخوذ من الواجهة المعلنة، ولم يُنفذ في البحث. يعيد إنشاء المهمة `task_id`؛ نتابع `GET /v1/tasks/{task_id}` مع `X-ModelScope-Task-Type: image_generation` حتى نجاح المهمة أو فشلها، ثم نحفظ الصورة الناتجة. عدد المراجع وأحجامها المقبولة فعلياً يُختبران على الإصدار والمزود المختارين. [المثال الرسمي](https://modelscope.cn/models/qwen/Qwen-Image-Edit-2511).

**العائق المتبقي:** حساب مؤهل، وتوثيق الهوية، ومفتاح، ثم اختبار جودة. لم يثبت البحث أن توثيق الحساب متاح لكل بلد أو وثيقة، ولا أن الوصول من شبكة المستخدم ناجح بمجرد إتاحة الوثائق العامة.

## 2. SiliconFlow + Kwai-Kolors/Kolors

صفحة التسعير الصينية تعرض **Kwai-Kolors/Kolors مجاناً لكل صورة**. في الصفحة نفسها Qwen-Image وQwen-Image-Edit مدفوعان؛ لذلك لا نربط نموذج Qwen هناك على أساس أنه مجاني. ولا نعمم تسعير الموقع الصيني على موقع SiliconFlow الدولي. [التسعير الرسمي](https://www.siliconflow.cn/pricing).

الواجهة `POST https://api.siliconflow.cn/v1/images/generations` تستخدم مفتاح حساب. المثال الرسمي لـKolors يتضمن الحقل `image`، بصيغة رابط أو Base64. إذن ليس دقيقاً وصف الخدمة بأنها نص إلى صورة حصراً. لكن `image2` و`image3` موثقان لنسخة Qwen-Image-Edit-2509، وليس لـKolors. روابط النتائج صالحة ساعة ويجب حفظها. [مرجع API](https://api-docs.siliconflow.cn/docs/api/images-generations-post).

**الحكم:** بديل مجاني يستحق تجربة التحرير بصورة واحدة والتوليد الإلهامي. قبول الصورة لا يثبت جودة تغيير الشعر أو حفظ الهوية أو دمج ملابس متعددة. لا نعطي رقماً يومياً لم يوثّق لحسابنا، ولا نفترض أهلية التسجيل أو التزامناً غير محدود.

**عائق حساب محتمل:** FAQ الموقع الصيني ينصح بأرقام شركات اتصالات الصين القارية، ويذكر إيقاف الربط عبر Google/GitHub مع وجود تسجيل دخول بالبريد للحسابات المعنية. هذا لا يثبت استحالة التسجيل من الخارج، لكنه يجعل نجاح التسجيل والأهلية اختباراً ضرورياً قبل اعتماد الخدمة. [أسئلة الحساب الرسمية](https://api-docs.siliconflow.cn/docs/userguide/faqs/misc_use).

الأوزان الأصلية متاحة، لكن **ترخيص كود Kolors هو Apache 2.0، وترخيص النموذج مختلف** وله شروط تخص الاستخدام التجاري والتسجيل. كما أن إضافات FaceID وInpainting وControlNet المنشورة لا يعني أن API المجاني يعرضها كلها. [المستودع](https://github.com/Kwai-Kolors/Kolors)، [ترخيص النموذج](https://github.com/Kwai-Kolors/Kolors/blob/master/MODEL_LICENSE).

## 3. Zhipu / BigModel + CogView-3-Flash

وثيقة الشركة تسمي **CogView-3-Flash نموذج توليد صور مجانياً**، وتصفه بأنه تحويل نص إلى صورة بدقات متعددة. يصلح لصور الإلهام أو لخدمة توليد نصي داخل الموقع، لكن الوثيقة لا تثبت استقبال صور مرجعية لتلبيس المستخدمة نفسها. لم نتحقق من الحصة أو تفعيل حسابنا باستدعاء فعلي. [وثيقة النموذج المجاني](https://docs.bigmodel.cn/cn/guide/models/free/cogview-3-flash).

**لا نخلط الخدمة بالأوزان:** لم يثبت أن أوزان النسخة المسماة `CogView-3-Flash` منشورة بنفس اسم API. توجد عائلة CogView مفتوحة مستقلة، منها **CogView4-6B** ببطاقة Apache 2.0، لكن ذلك لا يثبت أنها نفس نموذج Flash المستضاف. المستودع يقدم إعداداً بترميز نصي 4bit واستهلاك نحو 13–14GB GPU في جدول اختباره، ويوصي بـ32GB RAM؛ هذه ليست متطلبات مضمونة لكل إعداد. [مستودع CogView](https://github.com/zai-org/CogView4)، [أوزان CogView4-6B](https://huggingface.co/zai-org/CogView4-6B).

## هل Google Colab هو الحل المجاني الآلي؟

Colab مفيد للتجارب التعليمية في Notebook، لكن Google تقول إن الموارد المجانية غير مضمونة، وتقيّد استخدام الواجهة الخارجية بديلاً عن Notebook في الخطة المجانية، وخدمات الويب غير المرتبطة بالحوسبة التفاعلية. لذلك لا أوصي بتحويل Colab المجاني إلى خادم API دائم لهذا الموقع. [FAQ الرسمي](https://research.google.com/colaboratory/faq.html).

الخيار الأقوى إذا وفرت الجامعة جهاز GPU هو تشغيل خدمة استدلال نملك التحكم بها عليها، ويرسل إليها خادم الموقع الطلب آلياً. مجانية ذلك تخص إتاحة عتاد الجامعة لنا؛ ليست وعداً بأن جميع الأجهزة أو الكهرباء أو الاستضافة مجانية للجميع.

## بديل خارج الصين: Cloudflare + FLUX.2 klein 4B

أُدرج للفائدة العملية، **النموذج من Black Forest Labs وليس صينياً**. Cloudflare يستضيفه للتحرير بالمراجع؛ وثيقته تعرض إدخال الصور. يمكن ربطه بخادمنا مباشرة دون نقل الموقع كله إلى Cloudflare. [وثيقة النموذج](https://developers.cloudflare.com/workers-ai/models/flux-2-klein-4b/).

الخطة المجانية تعلن 10,000 Neurons يومياً. عند نفادها تفشل الطلبات في Free؛ تجاوزها المدفوع يتطلب خطة Paid. السعر الحسابي للنموذج 5.37 Neurons لكل بلاطة إدخال 512×512 و26.05 لكل بلاطة إخراج. هذه وحدات استهلاك ضمن الحصة، وليست طلباً بالدفع عند البقاء في Free. [التسعير الحالي](https://developers.cloudflare.com/workers-ai/platform/pricing/).

مثال تقريبي محسوب: خرج 1024×1024 مع ثلاثة مراجع بالحجم نفسه = 4×26.05 + 12×5.37 = 168.64 Neurons؛ نظرياً نحو 59 طلباً من رصيد 10,000 قبل أي استخدام آخر. هذا تقدير من جدول البلاطات، ويجب قياس الاستهلاك الفعلي؛ لا نعد بعدد صور ثابت. نحتاج Account ID ومفتاح Workers AI وحساباً مؤهلاً؛ لم نختبره مصادقاً عليه.

## ماذا يناسب جهاز المستخدم؟

المواصفات المقروءة سابقاً: **GeForce MX450 بذاكرة 2GB، RAM نحو 16GB، ومعالج i5-1135G7**. الجهاز مناسب لتطوير واجهة الموقع وخادم Node، وأولوية التوليد خدمة API مستضافة.

مسارات offload تقلل VRAM على حساب RAM والسرعة. عبارة OmniGen2 «أقل من 3GB» لا تثبت أنه يعمل تحت 2GB؛ ونجاح نموذج أخف في توليد صورة لا يثبت نجاح تعديل ملابس وهوية بعدة صور. لم نحمّل النماذج أو نقس سرعتها على الجهاز، ولا نوصي بتنزيل عشرات الجيجابايت قبل اختيار مسار مناسب.

## ترتيب التجربة والتنفيذ المقترح

1. **اختبار أهلية ModelScope أولاً:** التأكد من إمكان إتمام الحساب وربطه وتوثيقه، وظهور Qwen 2511 كمزود مجتمع، والرصيد والتكلفة الفعلية. هذه متطلبات إعداد المطور، لا خطوات تطلب من مستخدمات الموقع.
2. **اختبار مصغر بصور عامة مصرح بها:** تغيير التسريحة فقط، ثم الملابس فقط، ثم مراجع متعددة. نثبت seed حيث يتاح، ونغير عاملاً واحداً لتمييز استجابة النموذج من اختلاف عشوائي.
3. **إذا اجتاز الجودة:** ربطه بـNode كموفر صور، ومفتاحه على الخادم؛ إنشاء مهمة محلية مرتبطة بالحساب، ثم إرسال ومتابعة وحفظ النتيجة آلياً.
4. **إذا تعذر الحساب أو لم تنجح الجودة:** تجربة Cloudflare للمراجع المتعددة، وKolors لصورة واحدة؛ لا نستبدل صورة المستخدمة بشخص مولد ثم نسميه تجربة ملابسها.
5. **إذا تعذر مزود مجاني مؤهل:** استخدام GPU جامعي متاح وتشغيل Qwen أو محرر آخر، أو CatVTON للملابس مع محرر للشعر. الاختيار مشروط بالعتاد الفعلي ونتائج الاختبار.

### معايير قبول قبل تشغيل زر «جرّبي التسريحة» و«ولّدي الإطلالة»

- الصورة تتغير فعلاً عند طلب تسريحة مختلفة؛ تغيير لون الشعر وحده لا ينجح في اختبار شكل التسريحة.
- الوجه يبقى قابلاً للتعرف عليه، مع مراجعة بشرية للانحراف؛ لا نعد بتطابق بيومتري أو قياس جسم دقيق.
- القطعة تطابق المرجع في اللون والقصّة والتفاصيل الأساسية، مع رصد تغيير الأزرار أو النقوش أو طول الملابس.
- النتيجة صورة واحدة متماسكة، دون لوحات ملصقة أو أطراف مشوهة ظاهرة أو أجزاء مقطوعة غير مقصودة.
- مبدئياً: مجموعة 12 حالة متنوعة لكل مهمة رئيسية، وتسجيل نسبة النجاح وزمن الانتظار والمحاولات واستهلاك الحصة. هذه خطة قياس، وليست نتائج حدثت بالفعل.
- إعادة التوليد لا تنشئ مهام مكررة تلقائياً؛ ونفاد الحصة أو فشل المزود يظهر كحالة واضحة ولا يؤدي إلى فاتورة أو نتيجة وهمية.

### تفاصيل ربط تحافظ على تجربة تلقائية

المسار المقترح: اختيارات المناسبة والملابس والشعر → خادم الموقع → مهمة توليد → API المحرك → متابعة الحالة → حفظ الصورة في مساحة الحساب → عرض الصورة وتنزيلها.

تُرسل نسخة مناسبة الحجم من الصور المطلوبة فقط بعد بيان المزود للمستخدمة وموافقتها على إرسال صورها إليه. Base64 ليس تشفيراً ولا يحول الخدمة إلى تشغيل محلي. لا تسجل الصور أو المفاتيح في logs، ولا توضع الروابط الخاصة في ملف التوثيق. تُحفظ النتيجة قبل انتهاء رابط المزود، مع مهلة وحد أقصى لإعادة المحاولة وطابور يحترم التزامن.

**التوصية النهائية لهذا البحث:** نبدأ تجربة **ModelScope + Qwen-Image-Edit-2511** لأنه أقرب حاجةً إلى تعديل الشخص والملابس بمراجع، ونحتفظ ببديل قابل للتبديل. **Kolors المجاني خيار حقيقي** لكنه لا يُعتمد وحده للإطلالة الدقيقة قبل الاختبار. **CogView-3-Flash مجاني للتوليد النصي** ويخدم الإلهام أكثر من تجربة المستخدمة. البحث لا يحول أيّاً من هذه الخيارات إلى محرك مربوط ومختبر حتى ننفذ الاستدعاء ونراجع نتائجه.
